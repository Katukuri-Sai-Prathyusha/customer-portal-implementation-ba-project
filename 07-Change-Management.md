# 07 - Change Request & Change Management

## 1. Purpose

Change management is used to control changes to the approved project scope, requirements, timeline, resources, and deliverables.

The objective is to ensure that project changes are evaluated before approval and do not create uncontrolled scope expansion.

---

## 2. Change Request Process

All significant changes will follow the following process:

1. Change request is raised.
2. Business reason is documented.
3. Business Analyst analyzes the requirement.
4. Impact assessment is performed.
5. Technical team provides feasibility input.
6. Project Manager assesses timeline and resource impact.
7. Product/Business Owner reviews priority.
8. Change is approved or rejected.
9. Approved changes are added to the project backlog.
10. Requirements and project documentation are updated.
11. Change is communicated to affected stakeholders.

---

## 3. Change Impact Assessment

Each change will be assessed against:

- Scope
- Requirements
- Timeline
- Resources
- Cost
- Technical feasibility
- Risks
- Dependencies
- Testing effort
- Business impact
- Customer impact

---

# 4. Sample Change Request

## Change Request CR-001

### Change Title

Add Live Chat Support to the Customer Portal

### Request

The business has requested the addition of a live chat capability so customers can communicate directly with support agents through the portal.

### Business Reason

The business expects live chat to improve customer response time and provide customers with an additional support channel.

---

## 5. Impact Analysis

| Area | Impact | Assessment |
|---|---|---|
| Scope | High | New functionality required |
| Requirements | High | New functional requirements required |
| Timeline | Medium | Additional development and testing |
| Resources | Medium | Development and support resources required |
| Cost | Medium | Potential third-party service cost |
| Technical | Medium | Integration and infrastructure required |
| UAT | High | Additional UAT scenarios required |
| Customer Experience | High | New customer interaction channel |
| Risk | Medium | Additional operational dependency |

---

## 6. BA Impact Analysis

The Business Analyst would need to:

- Gather detailed live chat requirements.
- Identify impacted business processes.
- Define user stories.
- Create acceptance criteria.
- Identify affected stakeholders.
- Analyze integration requirements.
- Update the requirements documentation.
- Update the RTM.
- Identify new UAT scenarios.
- Assess customer impact.
- Communicate requirement changes to stakeholders.

---

## 7. Change Decision

### Recommendation

**Defer to Phase 2**

### Reason

The live chat feature provides business value but is not essential for the initial portal launch.

Including it in the initial release may increase:

- Project timeline
- Development effort
- Testing effort
- Integration complexity
- Operational support requirements

The feature can therefore be considered for a future release after the core portal capabilities are successfully launched.

# 8. Change Control Matrix

| Change Type | Example | Approval |
|---|---|---|
| Minor | Text/content update | Product Owner |
| Moderate | New portal functionality | Product + PM |
| Major | Significant scope change | Sponsor / Steering Committee |
| Critical | Change affecting go-live | Sponsor + PM + Product |

---

# 9. Change Management Principles

The project will follow these principles:

- No major scope changes without impact assessment.
- All approved changes must be documented.
- Stakeholders must understand the impact of changes.
- Requirements must remain traceable after changes.
- Changes affecting timeline or resources must be communicated.
- Deferred features should be documented for future releases.

---

# 10. Change Request Status

| Status | Meaning |
|---|---|
| Submitted | Change has been requested |
| Under Assessment | Impact analysis is in progress |
| Pending Approval | Awaiting decision |
| Approved | Change accepted |
| Rejected | Change not accepted |
| Deferred | Change moved to future release |
| Implemented | Change completed |
| Closed | Change formally completed |
